# 던전헬퍼 통계 연결

기존 봇 DB와 작업을 유지하며 별도 인증 서버의 집계만 조회합니다.
`DROP_STATS_ORIGIN`(HTTPS 인증 서비스 주소), `DROP_STATS_READ_KEY`(서비스 읽기 키),
`DROP_STATS_GUILD_ID`(지정 Discord 서버)를 설정한 뒤 시작하면 명령을 추가합니다.
설정하지 않으면 기존 명령 목록을 유지합니다.

- `/드랍통계`: 한국 시간 오늘 던전별 영혼석/마력석 획득률·수량, 햄순이로 완료한 횟수
- `/오늘랭킹`: 영혼석 TOP 5, 마력석 TOP 5 별도 수량 순위
- `/내기록`: Discord interaction의 요청자 ID로 조회하여 본인에게만 표시

획득률은 획득 개수 / 햄순이로 완료한 판수 × 100입니다.
돌별 수량·완료 판수·퍼센티지를 두 개의 짧은 표에 표시합니다.
이는 수량 대비 지표이므로 한 판에 여러 개를 얻으면 100%를 넘을 수 있습니다.
항상 해당 던전으로 구분된 판수만 그 던전의 행에 표시합니다.
미분류 판수는 표 아래에 한 번만 표시하며 각 던전으로 복제하지 않습니다.
획득률은 해당 던전의 기록된 완료 판수를 기준으로 표시합니다.
미분류 완료가 남아도 현재 기록된 획득 수량 / 해당 던전으로 분류된 완료 판수로 비율을 표시합니다.
이 수치는 현재 기록 기준의 비율이며 미분류 판수를 임의 배정하거나 수량을 보정하지 않습니다.
사용자 화면에는 `집계 불완전` 경고나 내부 진단 설명을 붙이지 않습니다.
획득 수량·분류된 던전별 판수·미분류 판수·전체 완료 합계는 그대로 표시합니다.
2026-10-03 운영자 기준에 따른 과거 허상 일괄 보정은 당시 자료에만 적용된 작업입니다.
이후의 미분류 기록은 허상으로 추정하지 않습니다. 수량과 전체 완료 횟수는 보존합니다.
완료 판수가 0이면 비율은 `—`로 표시합니다.

지정 서버 이외에서는 조회할 수 없습니다. 닉네임 멘션·마크다운을 이스케이프하고
응답 멘션을 꺼서 랭킹에 이름이 올라가도 알림을 보내지 않습니다.

이전 앱은 가방 증가량(구매·거래 포함), v1.3.12는 클리어 보상 패킷의 획득 수량을 보고합니다.
거래소 구매 제외는 별도 실증이 필요하며, 이번 완료 판수 수정으로 획득 수량을 변경하지 않습니다.
랭킹은 각 계열의 수량 기준입니다. 시세나 가격 환산 점수는 사용하지 않습니다.
앱이 직접 실행하지 않은 수동 플레이의 완료 횟수는 추정하지 않습니다.
다만 API의 `observations`에 AI가 실제로 확인한 완료가 있으면 `관측 N판`으로 표시합니다.
예를 들어 원념석 55개, 완료 관측 76판, 획득 관측 9판이면
`55개 / 관측 76판 / 11.8%`로 표시합니다. 이 비율은 55/76이 아니라 9/76입니다.
관측 획득률은 획득한 판 / 관측 완료 판수이며, 여러 개를 얻어도 획득한 판은 1판입니다.
같은 돌에 햄순이 완료와 AI 관측 모두 있으면 `햄순이 / 관측` 순서로 두 값을 표시합니다.
집계 범위가 다르므로 두 분모를 합산하거나 큰 값으로 바꾸지 않습니다.
`AI로 관측한 완료` 합계도 별도 표시하며 기존 `햄순이로 완료한 횟수`와
미분류 판수는 기존 완료 보고에서만 계산합니다. 랭킹과 가방 증가량은 변경하지 않습니다.
일별 날짜와 TOP 5는 인증 서버가 결정합니다.

읽기 키는 봇 서버에만 설정하고 사용자에게 노출하지 않습니다.
인증 서비스는 `supremiere/Dungeonhelper`의 `cloudflare/dungeonhelper-auth` 디렉터리에 있으며,
봇 DB와 분리된 Cloudflare D1에 집계를 저장합니다.

## 완료 미분류 진단

미분류는 전체 완료에서 알려진 던전별 완료 합계를 뺀 값입니다. 알 수 없는 던전 키를
정상 분류로 숨기거나, 획득 아이템/인접 보고만 보고 특정 던전에 배정하지 않습니다.
같은 던전의 여러 행은 합산합니다. API의 선택적 `unclassified_details`는 보존된
원본 보고의 진단 요약이며, 전체 판수나 미분류 분모를 바꾸는 근거가 아닙니다.
이 필드가 없는 구버전 API도 그대로 표시합니다. 개인 계정·입장 ID는 화면에 추가하지 않습니다.

2026-10-25 조사에서 미분류 302판은 6개 계정의 완료 보고 10건과 일치했습니다.
기존 DB에는 보고 버전/원문/입장 지역이 없고 해당 보고의 수량도 모두 0이어서
안전하게 던전을 확정해 복구할 수 있는 기록은 0판입니다. 일괄 보정하지 않습니다.

후속 운영 순서: Dungeonhelper의 `completion-report-audit.sql` 적용 → 호환 Worker 배포 →
새 Dungeonhelper와 이 봇 배포. 2026-10-26 병합 승인을 받았으며 봇 서버 배포는 사용자가 직접 진행합니다.
새 보고는 버전·현재 입장·역할·지역 확인 출처/실패 이유를 서버에 보존합니다.
서버의 원본 보존 기간 이후에는 집계만 남으므로 진단 상세 합계를 전체와 동일시하지 않습니다.

## 특별 허용 사용자 관리 (관리자 전용)

`DROP_STATS_ORIGIN`과 `DROP_STATS_GUILD_ID`를 재사용하며, 별도 서버 비밀 변수
`SPECIAL_USERS_ADMIN_KEY`를 추가로 설정하면 지정 서버에만 다음 명령어가 등록됩니다.

- `/특별허용 추가 사용자아이디:<Discord 사용자 ID>`
- `/특별허용 삭제 사용자아이디:<Discord 사용자 ID>`
- `/특별허용 목록` (25명씩 표시, 다음 페이지는 응답에 안내되는 `다음아이디` 입력)

서버에 가입하지 않은 사용자도 ID로 등록할 수 있습니다. 닉네임이나 멘션 대신
Discord의 사용자 ID 복사 기능으로 얻은 17–20자리 숫자를 문자열 그대로 입력합니다.
실제 ID는 코드/설정 예시에 미리 넣지 않습니다. 목록은 인증 서비스의 기존 D1에 저장됩니다.
추가·삭제 후 던전헬퍼 앱 재빌드/업데이트나 Worker 재배포는 필요 없습니다.

등록 메타데이터에 `default_member_permissions=8`(Administrator)과 서버 전용 설정을
지정해 일반 회원의 명령어 선택 목록에서 숨깁니다. 다른 서버와 DM에는 등록하지 않습니다.
실행 직전에도 지정 서버와 실제 Administrator 권한을 검사합니다. `서버 관리` 권한이나
관리자처럼 보이는 역할 이름만으로는 사용할 수 없습니다. 추가·삭제·목록·오류 응답 모두
명령어 실행자에게만 표시하며 사용자 멘션 알림을 끕니다.

Discord 서버 관리자는 서버의 통합 설정에서 명령어 표시 권한을 재정의할 수 있습니다.
표시 범위를 비관리자에게 확대하더라도 봇의 실행 권한 검사는 유지되어 요청을 거부합니다.
관리자 전용 노출을 유지하려면 이 명령어에 비관리자 예외 권한을 추가하지 않습니다.

### 최초 연결

1. Dungeonhelper 인증 Worker의 `special-allowed-users.sql` 마이그레이션을 적용합니다.
2. 통계 읽기 키와 **다른** 32자 이상 난수 비밀 값을 정해 Cloudflare Worker와 머장봇
   서버 양쪽의 `SPECIAL_USERS_ADMIN_KEY`에 동일하게 저장합니다. Worker에서는 Secret으로
   등록합니다. 사용자 앱·소스·공개 설정·디스코드 메시지에 넣지 않습니다.
3. 관리자 API를 포함한 인증 Worker와 이 봇 코드를 각각 배포하고 봇을 재시작합니다.
   기존 서버 명령어 동기화에서 지정 서버에 새 명령어를 등록합니다.

관리 키나 지정 서버/인증 주소가 없으면 새 명령어를 등록하지 않으며 기존 명령어는 유지합니다.
기존 `DROP_STATS_READ_KEY`는 조회 전용으로 남고, 그 키나 사용자 앱 세션으로 관리 API를
호출할 수 없습니다. 새 관리 키가 기존 읽기 키와 같으면 Worker가 관리 API만 비활성화합니다.
목록 삭제는 다음 로그인/갱신/복원 검사에 반영되며, 기존 Discord 서버 가입자는 계속 허용됩니다.

검증: 일반 회원·서버 관리 권한만 있는 회원·다른 서버 관리자·DM은 API 호출 전에 거부,
명령어 등록 권한 및 지정 서버 동기화, 관리자 응답 비공개, 잘못된 ID/서버 응답과 통계 기능
회귀 검증을 포함합니다. 실제 Discord 표시/실행 검증은 배포 후 별도 계정으로 확인합니다.
