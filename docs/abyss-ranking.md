# 어비스 랭킹

`/어비스랭킹 닉네임 [서버]`는 서버 내 직업 순위를 카드 제목에 표시합니다.
같은 이름이 여러 서버에 있으면 캐릭터 선택 메뉴를 제공합니다. 서버는 이름 또는
자동완성으로 지정할 수 있습니다. 닉네임은 앞뒤 공백·대소문자·유니코드 호환 문자를
정규화한 뒤 일치 검색합니다.

## 순위 범위

- 서버 내 직업 순위: 해당 서버·직업 API의 `rank` 그대로 표시합니다.
- 전체 종합 / 서버 종합 / 전체 서버 직업 순위: 집계된 랭커 중 더 높은 점수의
  기록 수에 1을 더합니다. 동점은 공동순위입니다.
- 데이터는 8개 서버 × 21개 직업의 상위 100명 표본입니다. 종합 순위는 게임의 모든
  캐릭터를 포함하는 공식 순위가 아니므로 카드에 `집계 랭커 중`이라고 표시합니다.
- 검색되지 않은 캐릭터를 미존재 또는 특정 순위로 단정하지 않습니다.

## API

모비라이프에 직접 요청합니다. 추가 API 키와 라이브러리는 필요 없습니다.
기존 Cloudflare Worker 허용 목록에 아래 두 경로가 필요합니다.
이번 작업에서는 사용자에 의해 두 경로가 배포된 뒤 실제 HTTP 200 응답을 확인했습니다.

```javascript
path === "/d/api/v1/abyss-rankings/seasons" ||
path === "/d/api/v1/abyss-rankings/table" ||
```

시즌 목록:

```http
GET /d/api/v1/abyss-rankings/seasons
```

```json
[
  {
    "season_start": "2026-08-12T21:00:00Z",
    "season_end": "2026-09-16T21:00:00Z"
  }
]
```

시즌 시각 문자열을 쿼리에 그대로 전달하며 화면의 날짜만 한국 시간으로 변환합니다.
다음 예시에서 서버 `01`은 데이안, 직업 `26`은 암흑술사입니다.

```http
GET /d/api/v1/abyss-rankings/table?season_start=2026-08-12T21%3A00%3A00Z&server=01&klass=26&sort=score
```

응답 구조 (실제 응답에서 Roxxy 행만 발췌; 원본 `entries`는 100개):

```json
{
  "season_start": "2026-08-12T21:00:00Z",
  "season_end": "2026-09-16T21:00:00Z",
  "snapshot_date": "2026-09-15",
  "previous_snapshot_date": "2026-09-14",
  "total": 100,
  "entries": [
    {
      "rank": 31,
      "character_id": 25007368437762,
      "character_name": "Roxxy",
      "server": "01",
      "klass": "26",
      "score": 75025,
      "score_delta": 0,
      "rank_delta": -2,
      "is_new": false,
      "avatar_url": "https://cdn.mabimobi.life/image/stellagram/avatar/8d/ac/8dacccd7c89669bd915177b1e7aa64a85046ce0189edf5801c5269b0f790e5b2.png"
    }
  ]
}
```

`score_delta`와 `rank_delta`의 `null`은 비교 기록 없음, 0은 변동 없음입니다.
`rank_delta > 0`은 순위 상승입니다. 서버 내 직업 순위의 변동으로 표시합니다.

## 갱신과 배포

- 기존 진입점 `python main.py`를 유지합니다. 새 명령어는 기존 서버별 동기화에 포함됩니다.
- 시작 시 SQLite 캐시를 복원하고, 없거나 6시간이 지나면 갱신합니다.
- 한 번의 전체 갱신은 시즌 요청 1회와 서버·직업별 표 요청 168회입니다.
  동시 요청은 최대 3개이며 사용자의 동시 조회는 진행 중인 갱신을 공유합니다.
- 최초 집계가 10초 안에 끝나지 않으면 준비 중 안내 후 백그라운드 집계를 계속합니다.
- API 실패·행 누락·서버/직업 필터 오류·정산일 불일치·DB 저장 실패 시 이전 캐시를
  보존합니다. 갱신 실패 후에는 최소 5분 간격으로 다시 시도합니다.
- 모든 그룹의 정산일이 같을 때만 DB와 메모리 캐시를 교체합니다. 지연된 데이터에는
  이전 기록 안내를 표시합니다.
- `abyss_ranking_cache` 테이블만 추가합니다. 기존 구독·공지·룬 통계 데이터는 유지됩니다.
- 새 서버나 직업이 추가되면 `sites/moblife/abyss_ranking.py`의 목록을 갱신해야 합니다.
