# 계획된 만남

평화와사랑 서버에서 일회성·예약·고정 파티를 모집한다. 파티장은 정원과 행선지를 직접 정한다. 출발 예정 시각은 한국시간으로 표시하며, 시각을 비워 둬도 생성할 수 있다. 파티방은 수개월이 지나거나 활동을 종료해도 유지된다.

## 최초 설정

1. 운영 중인 머장봇 역할에 메인·모집·홍보·관리자 로그 채널의 **채널 보기, 메시지 보내기, 메시지 기록 보기, 링크 첨부**를 허용한다. 메인 패널과 파티방 안내를 고정할 수 있도록 **메시지 고정**을 허용한다.
2. **서버 설정 → 역할 → 머장봇**에서 **채널 관리, 역할 관리, 채널 보기, 메시지 보내기, 메시지 기록 보기, 링크 첨부, 파일 첨부, 메시지 관리, 메시지 고정**을 허용한다. 파티방을 만들 카테고리에서도 봇이 채널을 관리할 수 있어야 한다. 일반 봇은 파티방의 권한을 바꿀 때 서버 역할의 **역할 관리**를 사용한다. 서버에서 이 권한을 가진 운영진은 방에 입장하면 Discord 자체의 권한 관리 기능도 쓸 수 있다. 서버 차원의 **감사 로그 보기** 권한이 있으면 채널 생성 응답을 받기 전에 봇이 꺼진 경우에도 생성 주체를 확인할 수 있다.
3. 기존 우만열차 관리자 계정으로 서버 안에서 `/계획된만남`을 실행한다. 서버 설정에서 **메인 패널 채널**, **모집 채널**, **홍보 채널**(기존 자유-채팅)을 선택한다. 파티를 만들면 모집 채널과 같은 카테고리에 비공개 텍스트 채널이 하나 생긴다. 모집 채널이 카테고리 밖에 있으면 파티방도 카테고리 밖에 생긴다. 다른 곳에 모으고 싶으면 **파티방 위치 (선택)**에서 카테고리를 지정한다. **모집 채널 위치 사용**으로 언제든 기본값을 복원할 수 있다. **관리자 로그 채널 (선택)**은 관리 알림을 받을 곳이다. 이 항목을 비워도 **관리자 모드 → 최근 관리자 로그**에서 기록을 열어볼 수 있다.
4. **홍보·모집 설정**에서 기본값을 확인하고 **기능 활성화**를 누른다. 초기값은 파티당 홍보 간격 60초, 최대 정원 90명, 사용자당 생성 개수 무제한, 미활동 표시 기준 30일이다. 네 값은 서버별로 변경할 수 있다. 미활동 기준은 관리자 목록에만 적용한다.

이후 일반 사용자는 메인 패널의 버튼으로 이용할 수 있다. 관리자 판정은 우만열차와 동일하며 서버 소유자·Discord 관리자와 머장봇 관리자 역할을 지원한다. 관리자 자격으로 접근하면 파티 정원을 그대로 유지한다.

## 파티·관전 이용

| 하고 싶은 일 | 이용 방법 |
| --- | --- |
| 파티 만들기 | **파티 생성**을 누르고 행선지와 파티장 포함 총인원을 입력한다. 관전을 처음부터 닫으려면 메인 패널에서 **관전 닫고 생성**을 누른다. |
| 일정 잡기 | 출발 예정에 `2026-12-05 22:00`처럼 한국시간을 입력한다. 파티 관리에서 날짜를 바꾸거나 비울 수 있다. |
| 파티원으로 들어가기 | 모집글·홍보글의 **참가하기**를 누르고 나에게 표시되는 파티방 링크를 연다. 파티원은 정원에 포함되며 자신의 로스터를 작성할 수 있다. |
| 채팅 관전하기 | 관전이 열린 파티에서 **관전하기**를 누르면 승인 절차 없이 입장한다. **새 파티의 기본값은 관전 허용**이다. 관전자는 이전 대화와 파티방 안내를 읽고 채팅·파일을 공유하며, 정원과 로스터에 포함되지 않는다. 정원이 찬 파티도 관전할 수 있다. |
| 관전 범위 바꾸기 | 파티장·관리자는 **파티 관리 → 관전 닫기**에서 기존 관전자까지 권한을 회수할 수 있다. 다시 열면 원하는 사람이 관전하기를 새로 누른다. 추방된 사용자는 재입장 허용 전까지 관전과 참가가 차단된다. Discord 관리자 및 머장봇 관리자는 관리 권한으로 계속 접근한다. |
| 고정 파티 재사용 | **활동 종료** 후 다음 일정에 **활동 재개**하고 출발 일시와 모집 상태를 조정한다. 명단·로스터·작전·채팅 기록은 같은 방에서 이어진다. |
| 최종 해산 | 파티장 또는 관리자가 **파티 해산**을 확정하면 해당 파티의 모집글, 자유 채팅 홍보글, 파티방과 그 안의 대화 기록이 삭제된다. 이전 버전에서 해산한 파티의 모집글과 홍보글도 업데이트 후 자동으로 정리된다. |

공략이나 작전은 파티방 안에서 공유한다. 공개 모집·홍보글에는 파티방 내부 정보가 실리지 않는다. 관전 허용 상태에서는 관전 중인 서버 구성원도 파티방 대화와 고정 안내를 볼 수 있다.

## 관리자와 장애 대응

- **관리자 모드 → 전체 파티·파티 검색**에서 가입 여부와 관계없이 파티방과 관리 화면을 연다. **복구 필요**에서 오류 원인을 보고 권한 또는 채널 설정을 고친 뒤 **권한·메시지 복구**를 누른다. 메인 패널은 **서버 설정 → 메인 패널 복구**에서 복구한다.
- 파티장이 서버를 떠나면 참가 순서상 다음 파티원에게 위임한다. 남은 파티원이 없으면 모집을 닫고 관리자가 후속 처리를 맡는다. Discord 개발자 포털의 **Bot → Privileged Gateway Intents → Server Members Intent**를 켠 뒤 `MEETINGS_MEMBER_INTENT=1`로 재시작하면 서버 탈퇴 이벤트를 즉시 받을 수 있다. 기본 설정에서는 분할 점검 중 실제 서버 탈퇴를 확인한다. 봇이 꺼진 동안 생긴 변동도 같은 방식으로 반영한다.
- 모집·관전이 끊겼을 때 Discord의 채널 수·채널별 권한 항목 한도와 봇 권한을 확인한다. 채널 하나당 권한 항목은 최대 1,000개이며 기본 역할, 봇, 관리자 역할과 개별 참가자·관전자가 포함된다. 카테고리가 가득 찼으면 새 카테고리를 마련한 뒤 설정을 바꾼다. [Discord 오류 코드 30060](https://docs.discord.com/developers/topics/opcodes-and-status-codes#json-json-error-codes)
- 봇을 재시작하면 처리 중이던 파티와 기존 자원을 서버별로 나누어 확인한다. 수동 삭제된 파티방은 새 방을 만들고 DB에 보존한 로스터·작전·안내를 복구한다. Discord에서 삭제된 실제 채팅 기록은 복원할 수 없다. 파티방 주제에 들어 있는 식별자를 유지한다. 등록된 채널의 식별자가 다르거나 생성 주체를 확인할 수 없으면 권한 변경·삭제를 멈추고 관리자에게 오류를 남긴다.
- 채널은 생성됐는데 DB에 채널 ID를 기록하기 전에 봇이 꺼졌다면, 봇에 **감사 로그 보기**를 부여하고 해당 파티의 **권한·메시지 복구**를 누른다. 관리자가 Discord 감사 로그에서 생성자·채널·작업 사유를 확인한다. 후보가 여럿이거나 감사 기록이 오래되어 자동 확인이 계속 실패하면 관련 채널을 그대로 보존하고, 관리자가 실제 파티방을 확인한 뒤 식별자 충돌을 수동 해결한다.
- 홍보 결과를 확인하기 전에 연결이 끊겼다면 기존 자유-채팅 게시물을 먼저 확인한다. 관리자 로그와 **복구 필요**에 표시된 원인을 해결한 뒤 복구를 실행한다. 실제 게시 여부를 판단할 수 없는 상태에서 같은 홍보 요청을 반복하면 안 된다.
- 홍보 채널에서 봇의 **메시지 기록 보기** 권한이 사라지면 이전 게시 여부를 확인할 수 없어 재발송을 보류한다. 권한을 되돌리고 해당 파티의 **권한·메시지 복구**를 누른다.

## 배포와 롤백

1. 머장봇과 같은 저장소·실행 환경에 변경 파일을 적용한다. 사전에 해당 버전에서 `python -m pytest -q`를 실행한다. 테스트 환경에는 프로젝트 의존성과 pytest가 필요하다.
2. 기존 봇을 중지하고 기존 코드 버전과 영구 볼륨의 SQLite `DB_FILE`을 백업한다. SQLite 백업 API나 운영 환경의 일관된 스냅샷을 사용한다. 동일한 봇 토큰·DB 조합에는 프로세스를 하나만 실행한다. Discord 채널·권한·메시지 변경의 파티별 직렬화는 봇 프로세스 안에서 이뤄진다.
3. 원래 사용하던 `.env`와 DB 경로로 `python main.py`를 실행한다. 시작 시 기존 DB에 `meeting_` 테이블과 인덱스를 추가한다. 서버별 기능은 관리자 설정 후 활성화된다.
4. 별도 테스트 서버에서 일반 계정·관전자·파티장·관리자 계정으로 실제 방의 열람·발언·권한 회수, 재시작 후 버튼, 자유-채팅 홍보, 해산 확인을 점검한 뒤 운영 서버에서 활성화한다.
5. 기능만 일시 중지하려면 서버 설정에서 비활성화한다. 코드 롤백은 봇을 중지하고 기존 코드 버전으로 되돌려 **현재 DB 그대로** 다시 실행한다. 이전 코드가 신규 파티 데이터를 사용하지 않으므로 SQLite 전체를 과거 백업으로 되돌릴 필요가 없다. 기존 Discord 파티방·메시지·권한은 남지만 이전 코드에서는 신규 버튼이 작동하지 않는다. 필요하면 재배포 후 관리자 패널에서 정리한다.

## 구현 위치와 테스트

| 위치 | 담당 기능 |
| --- | --- |
| `discord_bot/commands/meetings.py`, `discord_bot/commands/meeting_party.py` | 메인·관리자 패널, 참가·관전·홍보 버튼, 파티 관리, 로스터·작전 양식 |
| `services/meetings.py`, `discord_bot/meetings_sync.py` | 실행 시점의 권한 검증, 파티별 동시 요청 처리, Discord 채널·권한·모집글·홍보글 반영 |
| `storage/database.py`, `storage/meetings.py` | 기존 SQLite 초기화에 신규 스키마 연결. 파티원·관전자·추방 명단, 일정·작전, 서버 설정, 홍보 영수증·복구 상태와 운영 기록 저장 |
| `discord_bot/bot.py`, `discord_bot/meeting_jobs.py` | 기존 봇의 명령·영구 버튼 등록, 탈퇴·권한 변경 이벤트, 재시작 복구 |
| `config.py`, `.env.example` | 서버 탈퇴 이벤트 수신 옵션 |
| `README.md`, `docs/planned-meetings.md` | 기능 진입점과 운영 절차 |
| `tests/test_meetings.py`, `tests/test_meetings_discord.py`, `tests/test_meeting_discord_sync.py` | 실제 SQLite 트랜잭션, 가상 시계, 동시 참가·홍보, 접근 실패 보상과 장애 복구 |
| `tests/test_meeting_party_ui.py`, `tests/test_meeting_panels.py`, `tests/test_meeting_jobs.py` | 버튼·모달, 화면별 정보 공개 범위, 관리자·관전자 권한, 이벤트와 복구 순회 |

전체 회귀 검사는 저장소 루트에서 `python -m pytest -q`로 실행한다. 임시 SQLite와 모의 Discord 전송을 사용하며 운영 서버의 토큰과 채널이 필요하지 않다.
